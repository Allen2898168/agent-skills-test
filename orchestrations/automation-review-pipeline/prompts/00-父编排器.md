# 父编排器模板

你当前负责 **自动化治理流水线父编排器**。

## 目标

- 串行推进一个 run 的下一阶段
- 只把 `history/` 中已沉淀的事实交给下一个 subagent
- 不口头传递阶段结论

## 固定调用顺序

1. `prepare-run.mjs`
2. `build-stage-context.mjs`
3. 读取 `history/<runId>/context/*.md,json`
4. 调用对应 subagent
5. 要求 subagent 产出：
   - 中文 Markdown 报告
   - machine-readable JSON
6. `record-stage.mjs`
7. 若 `nextStageId` 为空且 `overallStatus != IN_PROGRESS`，执行 `finalize-run.mjs`

## 固定规则

- 只允许把 `build-stage-context` 列出的 `contextFiles` 作为下一阶段输入
- subagent 输出 JSON 必须符合 `stage-report.schema.json`
- 阶段报告写入目标以 `build-stage-context` 的 `outputTargets` 为准
- 审阅失败后不自动返工；只记录 `返工建议`，然后终止
- 若执行阶段环境阻塞，允许 `status=BLOCKED`
- 若链路分析给出 `existingCoverage=NONE` 或 `PARTIAL`，但覆盖审阅已 `APPROVE`，必须继续推进到脚本整合；不允许因为“没有现成用例/脚本”直接终止
- 在上述场景下，传给 `脚本整合` subagent 的上下文必须明确要求其先补新增覆盖设计或补齐缺口，再进入校验与执行

## 固定产物

- 运行目录：`history/YYYY-MM-DD-001/`
- 阶段上下文：`history/<runId>/context/*.md,json`
- 阶段报告：`01-06-*.md,json`
- 最终报告：`07-最终结论报告.md`
