# 转盘抽奖活动后管回归测试用例集

## 文档说明

- 适用范围：WEEX 活动后台 `活动列表 / 转盘抽奖` 及其依赖后管模块。
- 当前口径：以后管配置回归为主，部分用例包含前端联动回显校验。
- 当前版本：v3。
- 用例总数：56。
- 优先级说明：
  - `P0`：主链路、阻塞性能力、上线前必回归。
  - `P1`：高频配置链路、核心分支。
  - `P2`：补充分支、扩展模块。

| 报名模版 | 9 |

| 合计 | 56 |

## 执行前置条件

- 环境为 staging。
- 已具备活动后台登录态。
- 已准备可用验证码来源，用于 `上线`、`下线`、`删除` 等二次确认操作。
- 已准备至少一组可用测试数据：
  - 报名模版
  - 转盘抽奖任务
  - 奖品
- 回归过程中的文本字段，若页面展示 `0/N` 字符计数或 `maxlength`，需顺手检查长度限制。

## 推荐执行顺序

1. 奖品管理
2. 报名模版
3. 任务管理
4. 活动配置 / 活动信息
5. 活动列表
6. 上下线 / 状态流转

## 共性检查项

- 所有新增/编辑链路均不得只看接口 HTTP 200，必须做列表回查、详情回查或编辑回显校验。
- 凡是页面出现可见字符计数器或 `maxlength`，都要顺手检查长度限制。
- 下拉、多选、远程搜索类组件必须选中真实选项，不能只填输入框文本。
- 活动时间校验必须关注后台业务时区；近未来活动不要直接套本机时区。
- 涉及 `上线`、`下线`、`删除` 的操作，都必须验证二次确认弹窗、验证码输入和最终状态变化。
