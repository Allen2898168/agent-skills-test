# 转盘抽奖活动前端落地页回归测试用例集

## 文档说明

- 适用范围：WEEX 转盘抽奖活动前端落地页。
- 当前口径：以前端页面展示、抽奖交互、抽奖结果、奖励记录校验为主。
- 编排版完整用例库：`docs/test-cases/lottery-frontend-regression-library-orchestrated.md`
- 当前版本：v3。
- 用例总数：84。
- 优先级说明：
  - `P0`：主链路、阻塞性能力、上线前必回归。
  - `P1`：高频配置链路、核心分支、重要 UI 校验。
  - `P2`：补充分支、兼容性与观察性校验。

## 执行前置条件

- 环境为 staging。
- 已准备可正常访问的前端活动 URL。
- 活动前端 URL 按 `https://stg-www.weex.tech/zh-CN/events/draw/<活动别名>` 拼接。
- 活动必须为已上线状态。
- 已准备至少一组可登录测试账号。
- 如需验证五连抽，账号当前可用抽奖次数需大于等于 5。
- 如需验证二次权重，需提前创建专项活动配置。
- 如需验证库存异常，需提前准备库存不足场景。

## 状态污染执行规则

前端回归并非所有 case 都能任意顺序执行。凡是会改变 `报名态 / 次数态 / 奖励记录 / 库存态` 的 case，都要按状态机执行。

推荐主回归顺序：

1. 只读首屏组：`FE-79`、`FE-01`、`FE-07`、`FE-17`、`FE-19`
2. 未报名状态组：`FE-81`
3. 报名状态切换组：`FE-82`、`FE-83`
4. 次数准备组：`FE-84`、`FE-22`
5. 单抽事务组：`FE-32`、`FE-33`、`FE-34`、`FE-35`
6. 奖励记录组：`FE-48`、`FE-49`、`FE-50`

强约束：

- `FE-80` 与 `FE-81` 时间态互斥，不能在同一活动、同一时间窗口内混跑。
- `FE-81` 必须先于 `FE-82`；执行 `FE-82` 后，账号会从“未报名”变成“已报名”。
- `FE-84` 必须在“已报名且充值任务未完成”场景执行，不应与 `FE-81` 共用“未报名”初始态。
- `FE-32 ~ FE-35` 会消耗抽奖次数并写入奖励记录，建议按单次抽奖事务连续执行。
- `FE-48 ~ FE-50` 若只校验入口 / 弹窗 / 字段结构，可独立执行；若要校验最新中奖记录，应承接单抽后执行。
- 五连抽、小库存、二次权重必须拆到专项活动执行，不混入普通主回归。
