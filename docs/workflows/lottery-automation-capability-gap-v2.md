# 抽奖活动回归自动化能力差距清单 v2

## 文档说明

- 适用范围：WEEX 转盘抽奖活动后管回归、前端落地页回归、专项回归的自动化能力建设。
- 目标口径：支持用户说“进行抽奖活动回归测试”后，先展示已登记场景菜单，再按用户选择执行单场景、多场景或全部回归。
- 当前状态：已具备首版菜单编排、后管主回归入口、前端主回归首批入口；距离“整套抽奖活动全自动化回归”仍有剩余能力差距。

## 最终验收口径

后续只要满足这 6 条，就算达到目标：

1. 用户说“进行抽奖活动回归测试”时，系统固定先展示场景菜单。
2. 菜单只展示 manifest 中已登记场景，并标注可执行状态。
3. 用户可选择单场景、多场景、全部。
4. 调度器只执行用户选中的范围。
5. 每个场景执行前自动补齐对应前置条件。
6. 执行结束后输出场景级和 case 级结果明细。

## P0：必须先补齐的能力

### 1. 前端主回归真实执行验证

当前状态：`部分完成`

已具备：

1. 可按活动别名执行前端主链路。
2. 活动不存在时，可自动创建草稿并上线。
3. 已接报名、充值 MQ、单抽、奖励记录首批断言。
4. 已纳入 manifest，可被 dispatcher 选中。

还差：

1. 真实环境跑通 1 次普通前端主回归。
2. 固化稳定选择器与等待策略。
3. 确认真实执行证据可稳定映射到 case 结果。

验收标准：

1. 至少一轮真实执行可完成 `FE-79 / FE-81 / FE-82 / FE-83 / FE-32 / FE-33 / FE-34 / FE-35 / FE-48 / FE-49 / FE-50 / FE-84`。
2. 输出中每条 case 都有对应 evidence。

### 2. 前置条件自动补齐补全

当前状态：`部分完成`

已自动处理：

1. `ADMIN_SESSION`
2. `NORMAL_ACTIVITY_ONLINE`

未自动处理：

1. `FRONTEND_SESSION`
2. `NORMAL_ACTIVITY_SIGNED_UP`
3. `NORMAL_ACTIVITY_DRAW_GE1`
4. `REWARD_RECORD_DELAY_READY`
5. `NORMAL_ACTIVITY_DRAW_GT5`
6. `WEIGHT_ACTIVITY_ONLINE`
7. `WEIGHT_ACTIVITY_DRAW_GE3`
8. `LOW_STOCK_ACTIVITY_ONLINE`
9. `LOW_STOCK_ACTIVITY_DRAW_GT5`

验收标准：

1. 调度器在执行普通主回归时无需人工补普通活动与单抽前置。
2. 调度器在执行专项回归时可自动补齐对应专项活动和抽奖次数。

### 3. 主回归入口常态化可跑

当前状态：`部分完成`

已具备：

1. `lottery_admin_main_regression`
2. `lottery_frontend_main_regression`
3. `lottery-regression-dispatcher.mjs`

还差：

1. 调度器串起“后管主回归 + 前端主回归”后的真实执行验证。
2. 明确遇到 `partial / blocked` 场景时的输出口径。
3. 补一轮真实 dispatcher 级 dry-run 与 real-run 记录。

验收标准：

1. 执行“全部”时，当前可执行场景能稳定开始并输出结果。
2. `planned / blocked` 场景不会被误执行。

## P1：主链路稳定后补的能力

### 1. 五连抽专项

目标：

1. 覆盖 `FE-25 / FE-29 / FE-40 ~ FE-47`。
2. 单独验证“可用次数 > 5 时展示 抽奖 × 5 按钮”。
3. 小库存模板下补“五连抽被拦截，提示当日奖品所剩不多，请尝试单次抽奖”。

### 2. 二次权重专项

目标：

1. 覆盖 `AC-14` 与 `FE-64 ~ FE-67`。
2. 固化规则：若配置 `累计抽奖次数 N = 2` 且 `必中奖品 = 5`，则第 `3` 次抽奖命中奖品 `5`。

### 3. 小库存专项

目标：

1. 覆盖 `FE-23 / FE-45 / FE-46 / FE-57`。
2. 固化“库存不足提示弹窗”与“五连抽库存不足提示”断言。

### 4. 前端展示类 case 扩充

目标：

1. 扩充首屏 UI、标题、副标题、规则、奖池展示。
2. 扩充抽奖样式展示。
3. 扩充奖励记录多条记录、一致性、筛选等校验。

## 当前结论

如果现在有人说“进行抽奖活动回归测试”，系统已经能做到：

1. 展示后管/前端/专项的场景菜单。
2. 标出哪些场景可执行、部分可执行、未接自动化、当前阻塞。
3. 对已接入的后管主回归和前端主回归首批 case 生成执行计划。

但距离“整套抽奖活动后管 + 前端 + 专项全自动化回归”还差 3 个核心缺口：

1. 前端主回归真实环境常态跑通。
2. 专项活动与专项入口自动化。
3. 更完整的前置条件自动补齐。
