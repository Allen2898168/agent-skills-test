## LTR-BUG-001 转盘活动复制因源活动别名过长失败

- 来源：
  - 自动化主编排 `lottery_admin_main_regression`
  - 后管回归用例 `AC-15 活动复制`
  - 后管回归用例 `ST-03 草稿删除`
- 问题描述：
  - 在 `活动列表 / 转盘抽奖` 页面，对自动化创建的转盘活动执行操作列 `复制` 时，复制接口未成功创建新的草稿活动。
  - 研发反馈根因是：源活动配置的别名太长，导致复制活动失败；页面未给出明确“别名过长”提示，而是统一报 `system busy, please retry later`。
- 自动化发现方式：
  - 自动化脚本先创建并上线一个转盘活动。
  - 在列表页点击该活动操作列 `复制`。
  - 自动化回查复制后新草稿是否生成。
- 稳定复现条件：
  - 活动类型：`转盘抽奖`
  - 来源活动：自动化创建活动，别名类似 `lottery-admin-main-20260521234341`
  - 操作入口：活动列表行操作 `复制`
- 实际表现：
  - 触发 `POST /prod-api/activity/config/copy`
  - HTTP 状态：`200`
  - 业务返回：`code=500`
  - 返回文案：`system busy, please retry later`
  - 列表按复制目标别名回查：未生成新的草稿活动
- 影响范围：
  - `AC-15 活动复制` 无法通过
  - `ST-03 草稿删除` 当前自动化依赖“复制出草稿后再删除”的稳定路径，因此一起受阻
- 当前结论：
  - 这是自动化回归测试真实发现的缺陷，不是脚本误点，也不是未发请求。
  - 当前阻塞根因口径以研发反馈为准：`源活动配置的别名太长，导致复制活动失败`
  - 后续自动化默认活动别名应控制在 `10` 个字符以内；只有做别名边界值测试时，才允许显式使用更长别名。
  - 在研发修复前，自动化层只保留“阻塞事实”和失败证据，不再继续围绕复制链路做无效 debug
- 关联证据：
  - 后管主编排真跑结果中，`AC-15` / `ST-03` 失败，`ST-02` 同轮可通过
  - 失败接口：`POST /prod-api/activity/config/copy`
  - 失败文案：`system busy, please retry later`
- 后续处理建议：
  - 研发修复后，优先回归：
    - 复制后的新活动是否为草稿状态
    - 复制后的活动别名是否符合长度限制
    - `ST-03` 删除复制草稿链路是否恢复通过
