## LTR-BUG-002 转盘页语言切换未按预期进入英文态

- 来源：
  - 自动化主编排 `lottery_frontend_main_regression`
  - 前端回归用例 `FE-75 后管多语言配置后前端切语言展示正确`
- 问题描述：
  - 访问不带语言前缀的抽奖活动地址 `https://stg-www.weex.tech/events/draw/<alias>` 时，最终仍会被重定向回 `https://stg-www.weex.tech/zh-CN/events/draw/<alias>`。
  - 后管虽然已配置英文标题等多语言内容，但前端未进入预期英文态，导致该联动回归无法按“切语言后展示英文内容”口径稳定通过。
- 自动化发现方式：
  - 自动化读取后管多语言配置。
  - 前端访问去语言前缀的活动地址并回查最终 URL 与 `document.documentElement.lang`。
- 稳定复现条件：
  - 活动类型：`转盘抽奖`
  - 活动已上线，且后管已配置英文多语言内容
  - 访问入口：`/events/draw/<alias>`
- 实际表现：
  - 最终 URL 仍落在 `/zh-CN/events/draw/<alias>`
  - `document.documentElement.lang=zh-CN`
  - 页面未按预期进入英文态
- 影响范围：
  - `FE-75` 当前不能按“英文态前端展示”口径通过
  - 后续多语言前端联动回归需要依赖前端确认正确语言切换入口
- 当前结论：
  - 当前环境下“去语言前缀即英文态”不成立，可能存在强制中文路由或独立语言切换规则。
  - 这是前端行为问题，不是自动化脚本报错。
- 关联证据：
  - `skills/weex-frontend-ops/failure-reviews/draw-ui.md`
  - `docs/session-handoff.md`
- 后续处理建议：
  - 先由前端确认：
    - 抽奖活动页英文态的正确 URL 规则
    - 是否需要站内语言切换动作，而不是改 URL
