## 七、前端结果校验标准

### 1. 单抽

单抽自动化断言至少包含：

- 点击抽奖后成功发起请求
- 奖品弹窗展示正常
- 剩余次数减少 `1`
- 延迟 `5秒` 后，`我的奖品 -> 奖励记录` 中可查到新增结果
- 奖励记录字段正确：
  - `活动名称`
  - `奖励金额`
  - `获奖时间`
  - `备注`

### 2. 五连抽

五连抽自动化断言至少包含：

- 五连抽按钮展示条件正确
- 点击后成功发起请求
- 奖品结果弹窗展示正常
- 剩余次数减少 `5`
- 延迟 `5秒` 后，`我的奖品 -> 奖励记录` 中可查到新增结果
- 当前已确认：五连抽场景下，奖励记录按**多条记录**校验

### 3. 我的奖品 / 奖励记录

当前已确认命名口径：

- 页面入口名：`我的奖品`
- 点击后弹窗名：`奖励记录`

自动化断言至少包含：

- 点击入口可打开弹窗
- 奖励记录列表可展示数据
- 筛选交互可用
- 中奖弹窗与奖励记录结果一致

## 八、奖励记录时延处理

当前已确认：抽奖完成后，延迟 `5秒` 再检查 `我的奖品 -> 奖励记录`。

自动化建议：

- 先固定等待 `5秒`
- 再进入奖励记录断言

如果后续稳定性不够，再升级为：

- `5秒固定等待 + 轮询重试`

## 九、二次权重专项执行规则

当前已确认规则：

- 如果配置 `累计抽奖次数 N = 2`
- 且配置 `必中奖品 = 5`
- 则用户第 `3` 次抽奖命中奖品 `5`

即按 `N+1` 次开始生效。

自动化要求：

- 二次权重 case 必须使用专项活动执行
- 不要求验证二次权重的 case，不强制配置二次权重

推荐专项断言：

1. 第 `1`、`2` 次抽奖按普通配置执行。
2. 第 `3` 次抽奖命中指定奖品。
3. 奖励记录结果与二次权重配置一致。

## 十、小库存专项执行规则

当前已确认：

- 可以专门建一个活动，用于库存不足测试
- 该活动专门用于验证库存不足，不与普通回归活动共用

自动化目标：

- 验证库存不足时的前端反馈
- 当前先按“出现库存不足提示弹窗”断言

注意：

- 小库存活动不可复用为普通抽奖活动
- 跑完后活动状态已污染，下一轮应重新创建或复制新活动

## 十一、后管与前端自动化分工

### 后管自动化负责

- 模版、任务、奖品、活动配置创建和校验
- 活动上线 / 下线 / 删除 / 复制
- 奖池、任务、日历、多语言、FAQ 等配置回显
- 字符长度限制、字段显隐、保存成功校验

### 前端自动化负责

- 页面基础 UI 与样式展示
- 单抽 / 五连抽
- 按钮显隐与禁用态
- 奖品弹窗
- 我的奖品 / 奖励记录
- 前后端联动展示
- 库存不足提示、失败提示、异常恢复

## 十一、自动化执行顺序

### 主回归建议顺序

1. 后管依赖模块：
   - 报名模版
   - 任务管理
   - 奖品管理
2. 后管活动：
   - 活动列表
   - 活动配置 / 活动信息
   - 上下线 / 状态流转
3. 前端活动页：
   - 页面基础 UI
   - 单抽主流程
   - 我的奖品 / 奖励记录
4. 专项回归：
   - 五连抽专项
   - 二次权重专项
   - 小库存专项

## 十二、建议的自动化执行入口

后续建议在 skills 中最终形成 3 类入口：

### 1. 主回归入口

用途：
- 跑普通回归活动
- 覆盖稳定主链路

### 2. 二次权重专项入口

用途：
- 创建或复制专项活动
- 配置二次权重
- 执行 N+1 生效校验

### 3. 小库存专项入口

用途：
- 创建或复制小库存活动
- 执行库存不足提示校验

## 十三、当前不作为阻塞的问题

这些点当前已被用户确认，不阻塞自动化落地：

- 风控失败问题已解决，固定账号可用于报名与抽奖回归
- 并发问题当前不纳入主回归
- 概率统计当前只做二次权重专项，不做普通概率大样本统计
- 库存异常可通过独立小库存活动解决

## 十四、后续需要补充到 skills 的能力

为了真正让回归“自动跑起来”，后续 skills 需要补以下能力：

1. 新活动创建 / 复制后的标准化配置能力
2. 普通活动、二次权重活动、小库存活动三类活动模板能力
3. 固定账号登录和报名能力
4. 前置任务完成并领取抽奖次数的能力
5. 前端抽奖动作与奖励记录断言能力
6. 主回归与专项回归的入口编排能力
